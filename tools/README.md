# Сборка и деплой

Порядок обязателен: база → функции → приложение. Функция, задеплоенная
раньше своей миграции, пишет в несуществующий столбец; APK, собранный
раньше функции, показывает данные, которых сервер ещё не присылает.

```
./tools/deploy_server.sh          # 1. миграции + Edge Functions
./tools/build.sh features         # 2. APK из ветки features
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

`build.sh` останавливается на любой осечке: грязное дерево, разошедшаяся
ветка, упавшая сборка, APK без метки коммита. Ручная последовательность из
пяти команд ни одну из них не замечает — упавший `flutter build` просто
оставляет на диске прежний `app-release.apk`, и его же ставят на телефон.

## Как убедиться, что на телефоне нужная сборка

`build.sh` печатает коммит и вшивает его в APK через
`--dart-define=BUILD_ID`. В приложении он виден под заголовком экрана
«Одиночная Игра». Совпал с тем, что напечатал скрипт, — сборка та.

Сверить, не заходя в приложение:

```
ID=$(git rev-parse --short HEAD)
unzip -p build/app/outputs/flutter-apk/app-release.apk lib/arm64-v8a/libapp.so \
  | tr -d '\0' | grep -ac "$ID"
```

`tr -d '\0'` здесь обязателен: если метка попадёт в один строковый литерал
с кириллицей, Dart уложит её в снимок как UTF-16, и поиск по обычной строке
ничего не найдёт — хотя сборка при этом совершенно правильная.
