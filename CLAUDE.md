# Правила работы над этим проектом

## В конце каждого ответа — шаги для человека

Любая правка бага или новая возможность заканчивается списком того, что
нужно сделать владельцу проекта, командами, по порядку. Например:

```
git pull
./tools/release.sh Exp3
```

Плюс отдельно — что именно проверить руками на телефоне, если проверить
это можно только там. Без этого списка ответ не закончен: код, лежащий на
GitHub, до телефона сам не доезжает.

## Ветки

Разработка идёт в ветках, названных в задаче. Самовольно менять ветку
нельзя. Какие ветки есть — спрашивать у GitHub (`git ls-remote --heads
origin`), а не у списка внутри скрипта: такой список уже дважды устаревал
молча.

## Что ломается тихо

- Всё, что влияет на прогресс — балл, рейтинг, монеты, энергия, достижения
  — считает сервер через `security definer` RPC. Клиент в эти таблицы не
  пишет и своей копии счёта не держит.
- Прогресс принадлежит **изучаемому языку** (`user_languages`), а не
  аккаунту и не паре языков.
- `spend_energy` доступна только `service_role`. При нехватке она НЕ
  падает — списывает сколько есть. Значит, проверять остаток обязан тот,
  кто её зовёт, и до вызова.
- Ключей в репозитории не бывает: только в секретах Edge Functions.
  `.env` целиком уезжает внутрь APK — там место лишь `SUPABASE_URL` и
  `SUPABASE_ANON_KEY`.
- Новая Edge Function обязана попасть в `tools/deploy_server.sh` — иначе
  молча не задеплоится. Это сторожит тест.
- Контент (фразы, слова, фонотека) тянется с GitHub в рантайме, ветку
  задаёт `--dart-define=CONTENT_BRANCH`. Сборка мимо `tools/build.sh`
  читает контент из `main`.
- Форма вызова модели зависит от её СЕМЕЙСТВА (см. `_shared/asr.ts`).
  Мультимодальным нужен совместимый режим и `stream: true`; перепутанное
  семейство — это не падение, а отказ провайдера на живой записи.
- **Версия Android-плагина — это настройка сборки, а не мелочь.** У нас
  AGP 9.1.0 и `android.builtInKotlin=false`. Плагин, который применяет
  Kotlin Gradle Plugin по условию «если AGP младше 9», у нас Kotlin не
  компилирует вовсе — и падает это в ЧУЖОМ файле, `GeneratedPluginRegistrant
  .java`, с «cannot find symbol». Плагин, прибивший себе `compileSdk`
  гвоздями, падает на `checkReleaseAarMetadata`. Ни то ни другое сообщение
  не называет ни плагин, ни pubspec. Условное включение Kotlin сторожит
  тест; остальное видно только живой сборкой. Меняя версию плагина, читать
  его `android/build.gradle`, а не только CHANGELOG.
- **Уведомление ломается тишиной.** Не пришло — и отличить «правильно
  промолчали» от «receiver не объявлен» нельзя ничем: ни ошибки, ни лога.
  Молча ломают: отсутствие обоих `receiver` в манифесте, отсутствие
  `RECEIVE_BOOT_COMPLETED`, выключенный desugaring, выброшенные R8
  ресурсы (`res/raw/keep.xml`). Звук и вибрацию Android запоминает при
  СОЗДАНИИ канала и менять у существующего не даёт — меняя звук, менять
  `kReminderChannelId`. Имя значка передаётся ИМЕНЕМ РЕСУРСА
  (`ic_notification`), без `@drawable/`: с префиксом плагин отказывает на
  инициализации. Всё перечисленное сторожит `test/reminders_test.dart`.
- Собрать APK можно только там, где есть Android SDK. В облачной сессии
  его нет и не поставить (`dl.google.com` закрыт сетевой политикой), так
  что `flutter analyze` и `flutter test` — это НЕ проверка сборки, и
  говорить «собирается» по ним нельзя.

## Проверки перед тем, как сказать «готово»

```
flutter analyze lib test --no-fatal-infos --no-fatal-warnings
flutter test
```

Edge Functions — `deno check supabase/functions/*/index.ts`.

Тесты в этом проекте часто читают САМИ файлы (скрипты, SQL, TypeScript) и
проверяют, что написано в них, а не копию чисел рядом. Копия однажды
отстанет, и тест этого не заметит. Проверяя текст файла, смотреть на
команды, а не на любое упоминание: объяснение в комментарии — не код.

## Отложенные предложения

Улучшения, которые не меняют игровой цикл, не реализуются по собственной
инициативе — они записываются в `deferred_suggestions.md` и ждут
отдельного решения владельца.
