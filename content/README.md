# content/ — источник фраз и слов

Здесь лежат исходники всех фраз (`phrases_<уровень>.txt`) и слов
(`words_<уровень>.txt`) по языкам: `content/<код языка>/phrases_a1.txt`,
`content/<код языка>/words_a1.txt` и так далее для всех уровней
(a1, a2, b1, b2, c1, c2).

**Формат — одна фраза/слово на строку, без какой-либо разметки.** Никакого
JSON, кавычек, экранирования. Строка N любого языка — перевод строки N
английского файла того же уровня. Порядок строк и есть ключ соответствия,
отдельного id у фразы нет.

## Как добавить новую фразу

1. Допиши фразу новой строкой **в конец** `content/en/phrases_<уровень>.txt`.
2. Допиши её перевод новой строкой в конец `content/<lang>/phrases_<уровень>.txt`
   для **каждого** языка, у которого уже есть перевод на этом уровне.
   (Если на уровне сейчас переведено 100 фраз — после этого шага должно
   стать 101 у английского и у всех остальных языков, которые ты трогаешь.)
3. Собери JSON, который реально читает приложение:

   ```
   python3 tools/build_content.py
   ```

4. Закоммить и `content/`, и обновлённые `assets/phrases/*.json` /
   `assets/vocab/*.json` вместе.

Для слов — то же самое с `words_<уровень>.txt`.

## Правило «весь уровень или ничего»

Язык должен быть переведён **полностью** на уровне (все 100 фраз/1000 слов),
либо не быть переведён вовсе — частичный перевод уровня не поддерживается
(`PhraseBank.hasContentFor` / `FlashcardBank.hasContentFor` считают язык
готовым по принципу «есть хотя бы одна строка → должны быть все»). Поэтому
`tools/build_content.py` **требует**, чтобы число строк языка на уровне
точно совпадало с английским — при несовпадении сборка падает с понятной
ошибкой, а не молча сдвигает переводы на одну позицию.

Точно так же падает сборка, если внутри файла оказалась пустая строка —
она сдвинула бы соответствие для всех фраз после неё.

## assets/*.json — генерируемый файл, руками не редактировать

`assets/phrases/*.json` и `assets/vocab/*.json` — это то, что реально
грузит приложение (через `RemoteContent`/`PhraseBank`/`FlashcardBank`), и
их формат не изменился ни на байт. Но теперь это **сборочный артефакт**:
их пересобирает `tools/build_content.py` из `content/`, руками их больше
не трогают.

Проверить, не разошлись ли `content/` и `assets/` (например, в CI или перед
коммитом), не переписывая файлы:

```
python3 tools/build_content.py --check
```

## Проверка перевода обратным переводом

Для проверки качества перевода (не грамматики — смысла) используется
метод обратного перевода: переведённую фразу переводят обратно на
английский и сравнивают с оригиналом через эмбеддинги многоязычной модели.
Инструмент — `tools/verify_translation.py`, подробности запуска — в его
`--help` и в docstring файла.

## tools/split_content.py

Разовый скрипт, которым `content/` был изначально собран из уже
существовавших `assets/phrases/*.json` / `assets/vocab/*.json` (en, es,
ru). Для добавления новых фраз/языков он не нужен — используй шаги выше.
Оставлен как документация того, как появился `content/`, и на случай,
если понадобится ещё раз пересобрать content/ из assets/ с нуля.
