# Language Battle

Flutter (iOS + Android) + Supabase. Полная спецификация — во внутренней
документации проекта (`language_battle_game_spec.md`, передан отдельно).

## Статус

- **Фаза 0 (каркас)** — готово: Flutter-проект, схема БД раздела 4 + RLS,
  Auth email/password, базовая навигация.
- **Фаза 1 (полный цикл матча)** — готово: 10-раундовый матч в
  Состязании/Дуэли — запись, загрузка, прослушка голосовых, продвижение
  раундов и итоги через Realtime.
- **Фаза 2 (реальная оценка)** — готово: транскрипт снимается on-device
  (встроенный ASR Android/iOS), грамматику судит DeepSeek через Edge
  Function `evaluate-recording`, рейтинг/валюта/опыт считает RPC
  `finalize_match`. Подключение — `supabase/README.md`.
- **Дизайн** — переведён на палитру/шрифты `lexarena_mockups_v132.html`
  (Bungee/Baloo 2/Manrope/Space Mono, чёрно-жёлтая тема). Экраны логина и
  регистрации оставлены как есть по просьбе — не тронуты.
- **Магазин/Профиль/Друзья** — реальные данные из БД (покупка косметики,
  друзья, лидерборд по рейтингу). **Награды (Battle Pass)** — только визуальная
  заготовка, без бэкенда сезонов/квестов. **Матчмейкинг, аватар-редактор,
  push-уведомления, модерация** — не входят в этот проход, см. "Что дальше".

## Быстрый старт

1. Примените SQL-миграции к вашему Supabase-проекту — см.
   `supabase/README.md` (нужен доступ к SQL Editor в Supabase Studio).
2. Скопируйте `.env.example` в `.env` и впишите `SUPABASE_URL` /
   `SUPABASE_ANON_KEY` из Project Settings → API. **Никогда не кладите сюда
   `service_role` ключ или DeepSeek API key** — они не должны попадать в
   клиент, только в секреты Edge Function (см. `supabase/README.md`).
3. `flutter pub get`
4. `flutter run` (на реальном устройстве — для записи звука и
   распознавания речи нужен физический микрофон и доступ в интернет с
   телефона; на эмуляторе on-device ASR может работать хуже/не работать).

## Структура

```
lib/
  core/            Supabase-клиент, роутинг (go_router), тема/шрифты
  data/            локальный банк фраз (заглушка вместо LLM-генерации фраз)
  widgets/         переиспользуемые виджеты в стиле макета (LxPanel и т.п.)
  features/
    auth/          логин/регистрация (не менять — так и было задумано), сплэш-гейт
    onboarding/    выбор языков, никнейм
    arena/         главное меню + нижняя навигация + список активных боёв
    battle/        экран боя (запись/ASR/загрузка/прослушка, раунды) + итоги
    training/      Одиночная игра — пока заглушка (не в объёме этого прохода)
    profile/       реальная статистика (боёв/% побед/серия), инвентарь
    friends/       друзья/лидерборд/поиск — реальные данные
    shop/          каталог косметики + покупка/экипировка через RPC
    rewards/       визуальная заготовка Battle Pass, без бэкенда
supabase/
  migrations/      SQL: схема, RLS, storage, ИИ-триггер, прогрессия/магазин
  functions/       Edge Function evaluate-recording (DeepSeek) + общий LLM-адаптер
  README.md        как применить миграции и подключить ИИ-пайплайн
```

## Что дальше (не входит в этот проход)

- **Фаза 3** — живой матчмейкинг (сейчас матчи создаются вручную через
  Supabase Studio), fallback на бота, фоновый поиск с push.
- **Аватар-редактор** (экран 03 макета) — свой parametric-конструктор лица
  из SVG-слоёв. Сейчас везде простой круглый плейсхолдер с рамкой цвета лиги.
- **Battle Pass/квесты с реальным бэкендом** — таблицы есть, наполнение и
  ежедневный сброс не реализованы.
- **Друзья**: добавление сразу принимается (без экрана "входящие заявки").
- **Модерация/жалобы**, аналитика, локализация интерфейса, push-уведомления.

## Известное ограничение текущей сессии

Эта версия кода готовилась в среде без прямого сетевого доступа к
Postgres/Supabase (см. `supabase/README.md`) — миграции, деплой Edge
Function и живой прогон приложения нужно проверить самостоятельно на
машине/эмуляторе с реальным интернетом.
