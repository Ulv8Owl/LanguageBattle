# Language Battle

Flutter (iOS + Android) + Supabase. Полная спецификация — во внутренней
документации проекта (`language_battle_game_spec.md`, передан отдельно).

## Статус

- **Фаза 0 (каркас)** — готово: Flutter-проект, схема БД раздела 4 + RLS,
  Auth email/password, базовая навигация.
- **Фаза 1 (Wizard-of-Oz матч)** — готово: полный цикл матча в
  Состязании/Дуэли на 10 раундов с ручной постановкой баллов вместо
  реальной ИИ-оценки. Подробности и как гонять тест — `supabase/README.md`.

## Быстрый старт

1. Примените SQL-миграции к вашему Supabase-проекту — см.
   `supabase/README.md` (нужен доступ к SQL Editor в Supabase Studio).
2. Скопируйте `.env.example` в `.env` и впишите `SUPABASE_URL` /
   `SUPABASE_ANON_KEY` из Project Settings → API. **Никогда не кладите сюда
   `service_role` ключ** — он не должен попадать в клиент.
3. `flutter pub get`
4. `flutter run` (на реальном устройстве или эмуляторе — для записи звука
   нужен доступ к микрофону, на десктопных/веб-таргетах пакет `record`
   работать не будет так же надёжно, тестируйте на Android/iOS).

## Структура

```
lib/
  core/            Supabase-клиент, роутинг (go_router), тема
  data/            локальный банк фраз (заглушка вместо LLM-генерации)
  features/
    auth/          логин/регистрация, сплэш-гейт
    onboarding/    выбор языков, никнейм
    arena/         главное меню + нижняя навигация + список активных боёв
    battle/        экран боя (запись/загрузка/прослушка, продвижение
                    раундов) и экран итогов матча
    training/      Одиночная игра — пока заглушка
    profile/friends/shop/rewards/  заглушки Фазы 0
supabase/
  migrations/      SQL: схема + RLS + storage
  README.md        как применить миграции и прогнать ручной тест матча
```

## Известное ограничение текущей сессии

Эта версия кода готовилась в среде без прямого сетевого доступа к
Postgres/Supabase (см. `supabase/README.md`) — миграции и живой прогон
приложения нужно проверить самостоятельно на машине/эмуляторе с реальным
интернетом.
