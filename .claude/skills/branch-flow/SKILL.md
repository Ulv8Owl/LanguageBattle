# Ветки: main и features

Веток ровно две.

- **`main`** — последнее состояние, где всё работало. Эталон, к которому
  можно откатиться в любой момент. Ветка по умолчанию.
- **`features`** — всё новое. Любая новая задача идёт только сюда.

## Правило выбора ветки

Всё решает один вопрос: **что именно сломалось?**

| Что сообщает пользователь | Куда править | Что делать с main |
|---------------------------|--------------|-------------------|
| Новая задача | `features` | не трогать |
| Сломалось то, что работало ДО текущей задачи (регрессия) | `features` | не трогать |
| Замечание по самой текущей задаче — старое не сломано | сначала `features` → `main`, потом правки в `main` | обновить до features |

Смысл: в `main` попадает только то, что уже не ломает старый функционал.
Регрессия означает, что `features` ещё не готова — она остаётся в стороне,
а `main` продолжает быть рабочей точкой отката.

## Порядок действий

Новая задача или регрессия:
```
git checkout features
# правки
git commit && git push -u origin features
```

Замечание по текущей задаче (старое цело):
```
git checkout main && git merge --ff-only features
git push -u origin main
# дальше правки уже в main, и features подтягивается к ней
```

## Никогда

- Не коммитить новое напрямую в `main`, минуя `features`.
- Не сливать `features` в `main`, пока в ней есть регрессия.
- Не менять ветку молча: в ответе всегда писать, **в какую ветку** ушли
  правки и **почему** выбрана именно она.

## Откат

Если `features` увела не туда — `main` уже содержит рабочее состояние,
достаточно пересоздать `features` от неё:
```
git checkout -B features main
```
