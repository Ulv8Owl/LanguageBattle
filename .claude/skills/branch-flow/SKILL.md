# Ветки: стабильная и features

Веток ровно две.

- **`claude/sharp-feynman-ayfg57`** — стабильная: последнее состояние, где
  всё работало. Эталон, к которому можно откатиться в любой момент.
  Дальше по тексту — «стабильная».
- **`features`** — всё новое. Любая новая задача идёт только сюда.

## Правило выбора ветки

Всё решает один вопрос: **что именно сломалось?**

| Что сообщает пользователь | Куда править | Что делать со стабильной |
|---------------------------|--------------|--------------------------|
| Новая задача | `features` | не трогать |
| Сломалось то, что работало ДО текущей задачи (регрессия) | `features` | не трогать |
| Замечание по самой текущей задаче — старое не сломано | сначала `features` → стабильная, потом правки в стабильной | обновить до features |

Смысл: в стабильную попадает только то, что уже не ломает старый
функционал. Регрессия означает, что `features` ещё не готова — она
остаётся в стороне, а стабильная продолжает быть точкой отката.

## Порядок действий

Новая задача или регрессия:
```
git checkout features
# правки
git commit && git push -u origin features
```

Замечание по текущей задаче (старое цело):
```
git checkout claude/sharp-feynman-ayfg57 && git merge --ff-only features
git push -u origin claude/sharp-feynman-ayfg57
# дальше правки уже в стабильной, и features подтягивается к ней
```

## Никогда

- Не коммитить новое напрямую в стабильную, минуя `features`.
- Не сливать `features` в стабильную, пока в ней есть регрессия.
- Не менять ветку молча: в ответе всегда писать, **в какую ветку** ушли
  правки и **почему** выбрана именно она.

## Откат

Если `features` увела не туда — стабильная уже содержит рабочее
состояние, достаточно пересоздать `features` от неё:
```
git checkout -B features claude/sharp-feynman-ayfg57
```
